## 1. Implementation Status Classification Framework

Every subsystem, feature, algorithm, security control, and workflow in this report is assigned one or more of the following authoritative status classifications based on empirical repository evidence:

| Status Code | Definition |
| :--- | :--- |
| **IMPLEMENTED — CODE VERIFIED** | Source code exists in the repository, imports are valid, and the execution path has been traced end-to-end. |
| **AUTOMATED-TEST VERIFIED** | Dedicated automated regression, unit, or integration test suites exist and were executed with 100% passing results (exit code 0). |
| **DEPLOYED — DEPLOYMENT VERIFIED** | Live production deployment was inspected on Vercel and confirmed to serve the matching compiled bundles and API endpoints. |
| **PHYSICAL-DEVICE VERIFIED** | The feature was validated on a physical Android handset with hardware sensor logs. (Marked **PENDING** if device disconnected). |
| **PARTIALLY IMPLEMENTED** | Partial code or fallback simulation exists, but complete production capability requires additional native or server setup. |
| **DOCUMENTED ONLY** | Described in README, comments, or design proposals, but runtime execution logic is absent from production code paths. |
| **PLANNED / NOT IMPLEMENTED** | Identified as a proposed future enhancement or architectural recommendation. |
| **NOT EXPERIMENTALLY ESTABLISHED** | Biometric or statistical metrics (FAR, FRR, EER) that require large-scale empirical population datasets not present in this repo. |

## 3. Discrepancy & Reality Gap Register

The following table records all identified differences between historical documentation/README claims, source code reality, and physical verification:

| ID | Documented / Assumed Claim | Actual Codebase Reality | Root Cause & Evidence | Recommended Action / Status |
| :-: | :--- | :--- | :--- | :--- |
| **GAP-01** | **Face vectors stored in Supabase server database** | **DEVICE-ONLY BIOMETRICS**: Biometric templates are stored exclusively on the Android device in encrypted SQLite/Keystore; never transmitted to Supabase. | Architectural pivot for privacy compliance in migration `20261010_atomic_replace_face_biometrics.sql`. | Documented accurately as on-device privacy architecture. |
| **GAP-02** | **Attendance challenges include nodding and blinking** | **STRICTLY 4 HEAD MOVEMENTS**: Nodding (`NOD_ONCE`) and blinking (`BLINK_ONCE`) were completely removed from `liveness-engine.ts`. | User requirement to streamline attendance and eliminate unreliable nod/blink gestures on mobile cameras. | Verified removed across source, tests, and live production deployment. |
| **GAP-03** | **Dialog was floating and clipped off-screen on mobile** | **FULL-SCREEN 100DVH OVERLAY**: `FaceScanDialog` converted to `<DialogContent fullScreen={true}>` with `[transform:none]` and safe-area insets. | Tailwind v4 class conflict between `left-1/2` and `translate-x-0` displaced dialog off-screen to the right. | Resolved, tested across 6 viewport widths (320px–1280px), deployed live. |
| **GAP-04** | **Published 99.8% biometric accuracy metric** | **NOT EXPERIMENTALLY ESTABLISHED**: The repository does not contain an empirical benchmark dataset (e.g. LFW/IJB-C evaluation run on CampusAttend users). | Theoretical ArcFace paper metric was conflated with application benchmark. | Explicitly labeled as "Not Experimentally Established" in research paper. |
| **GAP-05** | **Physical Android hardware testing** | **TESTED VIA COMPREHENSIVE SIMULATION & ADB PENDING**: 123 node/tsx automated regression tests passed; ADB physical handset disconnected. | Development container does not have an attached physical Android phone via USB/Wi-Fi ADB. | Accurately reported as pending physical-device attachment. |
